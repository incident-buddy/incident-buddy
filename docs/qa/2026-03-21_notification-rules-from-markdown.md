### 合格項目

- **AC2**: 設定ファイルが存在しないパス指定時に通常フロー継続 → "設定ファイルが存在しない場合は通常フロー継続" で確認済み
- **AC3**: 設定ファイルの `Severities` セクションのラベルがモーダルのドロップダウンに説明文付きで表示される → "/inc コマンド - 設定ファイルのseverityがモーダルの選択肢に含まれる（説明文付き）" にて `"本番サービスが完全停止している"` など description の存在を確認済み
- **AC4**: 設定ファイルの `Services` セクションのサービス一覧がモーダルのドロップダウンに説明文付きで表示される → 同テストにて `"決済処理サービス"` など service description の存在を確認済み
- **AC5**: `severity: Critical`（完全一致）のルール評価 → "Critical + payment-api → 元チャンネル + #payment-oncall + #incidents-critical へ通知" で確認済み
- **AC6**: `severity: >= High`（以上比較）のルール評価 → "High + payment-api → #payment-oncall へ通知（Criticalルールはマッチしない）" で確認済み
- **AC7**: `severity: <= Medium`（以下比較）のルール評価 → "<= 演算子ルール: severity: Low でマッチし、High ではマッチしない" で確認済み（Low → #low-priority にマッチ、High → マッチしないことを両方検証）
- **AC8**: `service:` の大文字小文字無視マッチ → "service名の大文字小文字を無視してマッチする（Payment-API → payment-api）" で確認済み
- **AC9**: severity + service の AND 条件評価 → "Critical + payment-api → 2ルールマッチ" で確認済み
- **AC10**: マッチした全ルールのチャンネルへ追加通知が飛ぶ → 元チャンネル含む3チャンネルへの到達を確認済み
- **AC11**: `mention:` に記載したメンションが通知メッセージに含まれる → `@payment-lead`・`@here` の文字列存在を確認済み
- **AC12**: どのルールにもマッチしない場合は元チャンネルのみへ通知（現状維持） → "severity: Medium + service: payment-api → どのルールにもマッチせず元チャンネルのみ" で確認済み
